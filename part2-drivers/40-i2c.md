# Chapter 40 — I²C and SMBus

> **Goal:** master the cheapest bus in the system — two wires, no discovery, no error
> detection — and understand why that poverty forces every design decision in the subsystem,
> from device-tree enumeration to bus recovery.

---

## Theory & First Principles

### T.0 — Start here: two wires, and everything that follows from that

I2C uses **two wires** — one clock, one data — shared by every device on the bus. Philips
designed it in 1982 to connect chips inside a television, where the binding constraint was
**pin count on a cheap package**.

```
  VDD --+----------+---------- pull-up resistors (the bus is OPEN-DRAIN:
        R          R            devices can only pull LOW, never drive HIGH)
  SDA --+--+---+---+---+--
  SCL -----+---+---+---+--
           |   |   |   |
        master dev dev dev      every device has a 7-bit ADDRESS
```

**Every property of I2C is a consequence of "two wires, cheap":**

| Design choice | Because |
|---|---|
| **Open-drain** with pull-ups | Devices can only pull low, so two devices driving at once cannot destroy each other — arbitration comes for free |
| **7-bit addresses** (112 usable) | The address is sent on the data wire; more bits cost time |
| **Slow** (100 kHz standard, 400 kHz fast) | RC rise time through a pull-up resistor sets the ceiling |
| **No interrupt line** | Only two wires. A device needing to signal must use a *separate* GPIO |
| **No discovery** | There is no ID register. You must be *told* what is at address 0x48 (Ch. 31, Ch. 32) |
| **Master-driven** | Devices never initiate |

**The consequences for you as a driver author are immediate:**

```c
/* Every I2C access is a TRANSACTION over a slow serial wire. */
ret = i2c_smbus_read_byte_data(client, REG_TEMP);
/*    ^ this SLEEPS. At 100 kHz, one byte-register read is ~200 microseconds.
 *      You may NOT do this in an interrupt handler (Ch. 17 T.0).
 *      It can FAIL -- NAK, arbitration loss, a stuck bus.                  */
```

Compare with Ch. 34's `readl()` at ~100 ns. **I2C is roughly 2000x slower**, and that single
number determines the shape of every I2C driver: cache aggressively, batch into single
transactions, never poll in a loop, and use `regmap` with a register cache (Ch. 34 §T.7) so
repeated reads of the same register cost nothing.

**Two classic failure modes**, both of which you will eventually debug:

**Bus lockup.** A device pulled SDA low and the master was reset mid-transaction. The device
is waiting for clocks that will never come; the bus is stuck forever. Recovery is to manually
toggle SCL nine times so the device can finish its byte — which is why `i2c_recover_bus()`
and the `scl-gpios` device-tree property exist. A two-wire bus has no reset line, so recovery
must be improvised.

**Address collision.** Two sensors, both hardwired to 0x48, no way to change either. This is
why I2C **multiplexers** (`i2c-mux`) are a whole subsystem: the only fix for a 7-bit address
space is more buses.

**The general lesson**, and it is a good one for an architecture discussion:

> I2C's constraints were correct in 1982 and are now often wrong — but the bus is
> *everywhere*, in billions of devices, because it is nearly free to implement. **A
> technically inferior interface with dramatically lower cost wins, and then persists far
> beyond the conditions that justified it.**

```bash
i2cdetect -l                    # buses present
sudo i2cdetect -y 1             # scan bus 1 -- CAREFUL: a scan can confuse some devices
sudo i2cdump -y 1 0x48          # dump a device's registers
ls /sys/bus/i2c/devices/
cat /sys/kernel/debug/regmap/*/registers 2>/dev/null | head
```

### T.1 A bus designed for pennies, in 1982

Philips designed I²C to connect chips *inside a television set*. The constraints were:
two pins, no crystal on the slave, no addressing pins, and a cost target measured in cents.
Everything about the bus follows from that:

| Property | Consequence |
|---|---|
| **2 wires** (SDA, SCL) | no separate clock recovery, no full duplex, no chip-select |
| **Open-drain with pull-ups** | **wired-AND** — any device can pull low; nobody drives high |
| **Master-driven clock** | slaves need no oscillator |
| **7-bit addresses** | **112 usable** addresses per bus — collisions are a real board problem |
| **No CRC, no ACK of data content** | a single ACK bit per byte; corruption is undetectable |
| **No discovery protocol** | **the OS must be told what is present** (Ch. 31 T.1) |
| **No hotplug** | devices are soldered down |
| **100 kHz – 5 MHz** | slow; a 32-byte read takes ~300 µs at 100 kHz |

**The wired-AND electrical design is the elegant part**, and it buys two features for free:

1. **Multi-master arbitration with no protocol.** Two masters start transmitting; each
   reads back the line while driving it. A master that drives `1` but reads `0` has lost —
   another master drove `0`, which wins. It stops, and **the winning master never notices**.
   Arbitration is byte-by-byte, lossless, and costs zero extra wires or time. This is a
   genuinely beautiful piece of engineering.
2. **Clock stretching.** A slave that needs time holds SCL low. The master, which also reads
   SCL, waits. Flow control for free.

Clock stretching is also the bus's biggest practical problem: it is *optional*, many masters
implement it incompletely, and some SoC controllers cannot stretch at all. "This EEPROM works
on one board and not another" is very often clock stretching.

### T.2 No discovery means the firmware must describe everything

I²C has no equivalent of PCI's config space (Ch. 37 T.1). There is no vendor ID, no class
code, no way to ask "what are you?" So:

> **Every I²C device must be described in the device tree, in ACPI, or by board code.**
> This is Ch. 31 T.1's non-discoverable case in its purest form.

```dts
i2c1: i2c@1c2ac00 {
	compatible = "allwinner,sun6i-a31-i2c";
	reg = <0x01c2ac00 0x400>;
	clock-frequency = <400000>;          /* ★ bus speed is a BOARD property */
	#address-cells = <1>;
	#size-cells = <0>;                   /* ★ Ch. 32 T.4: address, no size */

	rtc@68 {
		compatible = "dallas,ds1307";
		reg = <0x68>;                /* the 7-bit slave address */
	};

	tmp@48 {
		compatible = "ti,tmp102";
		reg = <0x48>;
		interrupt-parent = <&gpio>;
		interrupts = <5 IRQ_TYPE_LEVEL_LOW>;
	};
};
```

**Probing an I²C bus blindly is dangerous, and this is worth stating loudly.** Writing to an
unknown address can:
- reprogram a PMIC's output voltage and destroy the board,
- put an EEPROM into a write cycle that corrupts calibration data,
- lock a device into a test mode requiring a power cycle.

Hence `i2cdetect` has a "quick write" mode that is *still* unsafe, and the kernel's
`detect()` callback mechanism is restricted to devices whose identification registers are
known to be safe to read. **The legacy `i2c_new_probed_device()` pattern is deprecated.**
The modern answer is always: describe it in firmware.

```bash
i2cdetect -l                        # list adapters
sudo i2cdetect -y -r 1              # -r = SMBus read byte (safer than quick-write)
sudo i2cdetect -F 1                 # what functionality does this adapter support?
ls /sys/bus/i2c/devices/            # 1-0068 = bus 1, address 0x68
cat /sys/bus/i2c/devices/1-0068/{name,modalias}
```

### T.3 SMBus: the disciplined subset

I²C says nothing about *what bytes mean*. **SMBus** (Intel, 1995) adds a protocol layer with
defined transaction types, so a generic tool can talk to a compliant device:

| SMBus transaction | Wire form |
|---|---|
| Quick command | `S addr+W A P` — just the address bit |
| Send/Receive byte | one byte, no register |
| **Read/Write byte data** | `S addr+W A cmd A data A P` — **register-addressed** |
| **Read/Write word data** | two data bytes |
| **Block read/write** | length-prefixed, ≤32 bytes |
| Process call | write-then-read in one transaction |
| **PEC** | an optional CRC-8 appended — the error detection I²C lacks |

SMBus also mandates timeouts (a slave holding SCL > 35 ms is an error, so the bus cannot hang
forever) and a minimum clock speed. It is what lets one `i2c-tools` binary read any SPD
EEPROM, any hwmon chip, any battery.

**The practical importance:** most simple I²C peripherals *are* SMBus-shaped
(register-addressed byte/word access), which is exactly why `regmap` (Ch. 34 T.7) fits them
so well.

```c
/* SMBus helpers — use these when the device is SMBus-shaped */
s32 v = i2c_smbus_read_byte_data(client, REG_STATUS);
i2c_smbus_write_byte_data(client, REG_CTRL, 0x42);
s32 w = i2c_smbus_read_word_data(client, REG_VALUE);       /* little-endian */
s32 w = i2c_smbus_read_word_swapped(client, REG_VALUE);    /* big-endian device */
i2c_smbus_read_i2c_block_data(client, REG_BASE, 16, buf);
i2c_smbus_write_block_data(client, REG_BASE, len, buf);

/* Raw I²C — when the device is NOT SMBus-shaped */
struct i2c_msg msgs[2] = {
	{ .addr = client->addr, .flags = 0,        .len = 2, .buf = regaddr },
	{ .addr = client->addr, .flags = I2C_M_RD, .len = n, .buf = data    },
};
ret = i2c_transfer(client->adapter, msgs, 2);   /* ★ a REPEATED START between them */
```

The two-message form with no STOP between them is the **repeated start**, and it matters:
it makes the register-set and the read atomic with respect to other masters. A driver that
does two separate `i2c_transfer()` calls has a race on a multi-master bus.

**Adapter functionality must be checked** — not every controller supports every transaction:

```c
if (!i2c_check_functionality(client->adapter,
			     I2C_FUNC_SMBUS_BYTE_DATA | I2C_FUNC_I2C))
	return -EOPNOTSUPP;
```

### T.4 The three-layer model

```
   i2c_driver     ← your driver, binds to an i2c_client
        │
   i2c_client     ← one device at one address on one adapter  ("1-0068")
        │
   i2c_adapter    ← a bus instance
        │
   i2c_algorithm  ← how to actually shift bits: ->master_xfer() / ->smbus_xfer()
        │
   controller driver (i2c-designware, i2c-imx, i2c-gpio, i2c-stub, ...)
```

The `i2c_algorithm` split exists so that **bit-banged** adapters (`i2c-gpio`, `i2c-algo-bit`)
and hardware controllers present the same interface. That is how you bring up a board before
the real controller driver works: drive SDA/SCL from two GPIOs and everything above the
algorithm layer is unchanged.

```c
static const struct i2c_device_id my_ids[] = {
	{ "mysensor", (kernel_ulong_t)&v1_data },
	{ }
};
MODULE_DEVICE_TABLE(i2c, my_ids);

static const struct of_device_id my_of_ids[] = {
	{ .compatible = "acme,mysensor", .data = &v1_data },
	{ }
};
MODULE_DEVICE_TABLE(of, my_of_ids);

static struct i2c_driver my_driver = {
	.driver = {
		.name           = "mysensor",
		.of_match_table = my_of_ids,
		.pm             = pm_ptr(&my_pm_ops),
	},
	.probe    = my_probe,          /* ★ modern form: takes only i2c_client */
	.remove   = my_remove,
	.id_table = my_ids,
};
module_i2c_driver(my_driver);
```

### T.5 Every transfer sleeps — and the consequences

An I²C transaction at 100 kHz takes **tens to hundreds of microseconds**. The controller
driver therefore sleeps waiting for completion. This single fact determines your whole driver
structure:

| Consequence | Rule |
|---|---|
| Cannot be called from atomic context | no I²C in a hardirq handler, a spinlock region, or `rcu_read_lock()` |
| Interrupt handlers must be threaded | `request_threaded_irq(irq, NULL, thread_fn, IRQF_ONESHOT, ...)` (Ch. 17 T.7) |
| Register caching is very valuable | `regmap` with `REGCACHE_MAPLE` (Ch. 34 T.7) |
| Polling loops must sleep | `regmap_read_poll_timeout()`, never `udelay` loops |
| A slow device can block others | the adapter is serialized by `i2c_lock_bus()` |

**The panic/shutdown exception.** A PMIC that must be poked to power off the board, or a
watchdog that must be kicked from a panic handler, cannot sleep. The
**atomic transfer** API exists for exactly this:

```c
/* Only valid when irqs are disabled and we are shutting down / panicking */
i2c_transfer_buffer_flags(client, buf, len, I2C_M_RD);   /* normal */
/* atomic variants used by reboot/poweroff handlers: */
ret = i2c_smbus_xfer(adap, addr, flags, read_write, command, size, &data);
/* controller must implement ->master_xfer_atomic / ->smbus_xfer_atomic */
```
Very few controllers implement it. If your board's power-off path needs I²C, verify this
early — it is a classic late-stage bring-up surprise.

### T.6 Bus recovery: when a slave hangs the bus

A real, recurring production failure: a slave is reset (or glitched) in the middle of a
transfer while it is driving SDA low. Now **SDA is stuck low** and no master can generate a
START condition. The bus is dead until power cycle.

The standard recovery is defined by the spec and implemented generically:

```
1. Release SDA (the master stops driving it).
2. Toggle SCL up to 9 times.
   → the slave shifts out its remaining bits and eventually releases SDA.
3. Generate a STOP condition.
```

Linux provides this generically; a controller driver just supplies the primitives:

```c
static struct i2c_bus_recovery_info my_recovery = {
	.recover_bus     = i2c_generic_scl_recovery,
	.set_scl         = my_set_scl,
	.get_scl         = my_get_scl,
	.set_sda         = my_set_sda,
	.get_sda         = my_get_sda,
	.get_bus_free    = my_get_bus_free,
	.prepare_recovery = my_prepare,      /* switch pinmux to GPIO mode */
	.unprepare_recovery = my_unprepare,  /* switch back to I2C mode */
};
adap->bus_recovery_info = &my_recovery;
```

The `prepare`/`unprepare` hooks are the interesting part: on most SoCs the pins must be
**re-muxed from the I²C controller to GPIO** to bit-bang the recovery, then muxed back
(Ch. 42). The DT expresses this with `pinctrl-names = "default", "gpio";` plus
`scl-gpios`/`sda-gpios`.

```dts
i2c1: i2c@1c2ac00 {
	pinctrl-names = "default", "gpio";
	pinctrl-0 = <&i2c1_pins>;
	pinctrl-1 = <&i2c1_gpio_pins>;
	scl-gpios = <&gpio 4 GPIO_OPEN_DRAIN>;
	sda-gpios = <&gpio 5 GPIO_OPEN_DRAIN>;
};
```

**If you are doing board bring-up (Ch. 101), wire this up on day one.** It converts "the
board is bricked, power cycle it" into "a message in dmesg and the system continues."

### T.7 Muxes, gates, and the address-collision problem

112 addresses sounds like plenty until you need four identical temperature sensors with a
fixed address. The solutions, all supported by `drivers/i2c/muxes/`:

| Mechanism | What it does |
|---|---|
| **I²C mux** (PCA9548) | one upstream bus → N downstream buses; select one at a time |
| **I²C gate** (PCA9515) | a switch that isolates a segment (for electrical reasons) |
| **Arbitrator** | two masters coordinate access via GPIOs before driving the bus |
| **`i2c-demux-pinctrl`** | one device reachable from two *different* controllers |

The mux core creates **child adapters**, so downstream devices look completely normal — a
sensor on `i2c-3` behind a mux has no idea. Selection happens automatically around each
transfer, with locking so two transfers on different mux legs cannot interleave.

```dts
i2cmux@70 {
	compatible = "nxp,pca9548";
	reg = <0x70>;
	#address-cells = <1>;
	#size-cells = <0>;
	i2c@0 {
		reg = <0>;
		#address-cells = <1>;
		#size-cells = <0>;
		tmp@48 { compatible = "ti,tmp102"; reg = <0x48>; };
	};
	i2c@1 {
		reg = <1>;
		tmp@48 { compatible = "ti,tmp102"; reg = <0x48>; };   /* ★ same address, different leg */
	};
};
```

```bash
i2cdetect -l                      # muxes create extra adapters
ls /sys/bus/i2c/devices/i2c-*/
cat /sys/bus/i2c/devices/i2c-3/name      # "i2c-1-mux (chan_id 0)"
```

### Lab 40.2 — A complete I²C sensor driver

```c
// SPDX-License-Identifier: GPL-2.0
/*
 * tmpdemo — an I²C temperature sensor driver.
 *
 * Demonstrates: regmap over I²C with caching, a threaded IRQ (T.5),
 * hwmon registration, runtime PM, and firmware-agnostic properties.
 */
#define pr_fmt(fmt) KBUILD_MODNAME ": " fmt

#include <linux/bitfield.h>
#include <linux/hwmon.h>
#include <linux/i2c.h>
#include <linux/interrupt.h>
#include <linux/module.h>
#include <linux/pm_runtime.h>
#include <linux/regmap.h>

#define TMPD_REG_TEMP     0x00      /* volatile, read-only, big-endian 16-bit */
#define TMPD_REG_CONF     0x01
#define  CONF_SHUTDOWN    BIT(8)
#define  CONF_RESOLUTION  GENMASK(14, 13)
#define  CONF_ALERT       BIT(5)
#define TMPD_REG_TLOW     0x02
#define TMPD_REG_THIGH    0x03
#define TMPD_REG_MAX      0x03

struct tmpd_variant {
	const char *name;
	int         resolution_bits;
	int         conv_time_ms;
};

static const struct tmpd_variant tmpd_v1 = { "tmpd-v1", 12, 26 };
static const struct tmpd_variant tmpd_v2 = { "tmpd-v2", 13, 35 };

struct tmpd {
	struct regmap             *regmap;
	struct device             *dev;
	const struct tmpd_variant *var;
	struct mutex               lock;
	u32                        alert_high_mC, alert_low_mC;
	u64                        alerts;
};

static bool tmpd_volatile_reg(struct device *dev, unsigned int reg)
{
	return reg == TMPD_REG_TEMP;            /* ★ never cache the measurement */
}
static bool tmpd_writeable_reg(struct device *dev, unsigned int reg)
{
	return reg != TMPD_REG_TEMP;
}

static const struct regmap_config tmpd_regmap_config = {
	.reg_bits          = 8,
	.val_bits          = 16,
	.max_register      = TMPD_REG_MAX,
	.volatile_reg      = tmpd_volatile_reg,
	.writeable_reg     = tmpd_writeable_reg,
	.cache_type        = REGCACHE_MAPLE,
	.val_format_endian = REGMAP_ENDIAN_BIG,  /* ★ Ch. 02 T.3: the device is big-endian */
};

/* raw 12/13-bit two's-complement, 0.0625 °C/LSB, left-justified in 16 bits */
static int tmpd_raw_to_mC(struct tmpd *t, unsigned int raw)
{
	int shift = 16 - t->var->resolution_bits;

	return (int)sign_extend32(raw >> shift, t->var->resolution_bits - 1) * 625 / 10;
}
static unsigned int tmpd_mC_to_raw(struct tmpd *t, int mC)
{
	int shift = 16 - t->var->resolution_bits;

	return ((mC * 10 / 625) << shift) & 0xffff;
}

static int tmpd_read_temp(struct tmpd *t, int *mC)
{
	unsigned int raw;
	int ret;

	ret = pm_runtime_resume_and_get(t->dev);
	if (ret)
		return ret;

	guard(mutex)(&t->lock);
	ret = regmap_read(t->regmap, TMPD_REG_TEMP, &raw);   /* ★ sleeps (T.5) */
	pm_runtime_mark_last_busy(t->dev);
	pm_runtime_put_autosuspend(t->dev);
	if (ret)
		return ret;

	*mC = tmpd_raw_to_mC(t, raw);
	return 0;
}

/* ★ T.5: the handler MUST be threaded — it does I²C */
static irqreturn_t tmpd_alert_thread(int irq, void *data)
{
	struct tmpd *t = data;
	int mC, ret;

	ret = tmpd_read_temp(t, &mC);
	if (ret)
		return IRQ_NONE;

	t->alerts++;
	dev_warn_ratelimited(t->dev, "ALERT: %d.%03d degC\n", mC / 1000, abs(mC % 1000));
	hwmon_notify_event(t->dev, hwmon_temp, hwmon_temp_alarm, 0);
	return IRQ_HANDLED;
}

/* ---- hwmon (the right subsystem for a temperature sensor — Ch. 29 T.9) ---- */

static umode_t tmpd_hwmon_visible(const void *data, enum hwmon_sensor_types type,
				  u32 attr, int ch)
{
	switch (attr) {
	case hwmon_temp_input:
	case hwmon_temp_alarm:
		return 0444;
	case hwmon_temp_min:
	case hwmon_temp_max:
		return 0644;
	default:
		return 0;
	}
}

static int tmpd_hwmon_read(struct device *dev, enum hwmon_sensor_types type,
			   u32 attr, int ch, long *val)
{
	struct tmpd *t = dev_get_drvdata(dev);
	unsigned int raw;
	int mC, ret;

	switch (attr) {
	case hwmon_temp_input:
		ret = tmpd_read_temp(t, &mC);
		if (ret)
			return ret;
		*val = mC;
		return 0;
	case hwmon_temp_max:
		ret = regmap_read(t->regmap, TMPD_REG_THIGH, &raw);   /* cached! */
		if (ret)
			return ret;
		*val = tmpd_raw_to_mC(t, raw);
		return 0;
	case hwmon_temp_min:
		ret = regmap_read(t->regmap, TMPD_REG_TLOW, &raw);
		if (ret)
			return ret;
		*val = tmpd_raw_to_mC(t, raw);
		return 0;
	default:
		return -EOPNOTSUPP;
	}
}

static int tmpd_hwmon_write(struct device *dev, enum hwmon_sensor_types type,
			    u32 attr, int ch, long val)
{
	struct tmpd *t = dev_get_drvdata(dev);
	unsigned int reg = (attr == hwmon_temp_max) ? TMPD_REG_THIGH : TMPD_REG_TLOW;

	if (val < -55000 || val > 150000)
		return -EINVAL;
	guard(mutex)(&t->lock);
	return regmap_write(t->regmap, reg, tmpd_mC_to_raw(t, val));
}

static const struct hwmon_channel_info *const tmpd_info[] = {
	HWMON_CHANNEL_INFO(temp, HWMON_T_INPUT | HWMON_T_MIN | HWMON_T_MAX | HWMON_T_ALARM),
	NULL
};
static const struct hwmon_ops tmpd_hwmon_ops = {
	.is_visible = tmpd_hwmon_visible,
	.read       = tmpd_hwmon_read,
	.write      = tmpd_hwmon_write,
};
static const struct hwmon_chip_info tmpd_chip_info = {
	.ops = &tmpd_hwmon_ops, .info = tmpd_info,
};

/* ---- probe ---- */

static int tmpd_probe(struct i2c_client *client)
{
	struct device *dev = &client->dev;
	struct device *hwmon;
	struct tmpd *t;
	unsigned int conf;
	int ret;

	/* ★ T.3: check what the adapter can actually do */
	if (!i2c_check_functionality(client->adapter, I2C_FUNC_SMBUS_WORD_DATA))
		return dev_err_probe(dev, -EOPNOTSUPP, "adapter lacks word transfers\n");

	t = devm_kzalloc(dev, sizeof(*t), GFP_KERNEL);
	if (!t)
		return -ENOMEM;
	t->dev = dev;
	mutex_init(&t->lock);
	i2c_set_clientdata(client, t);
	dev_set_drvdata(dev, t);

	t->var = i2c_get_match_data(client);      /* ★ works for DT, ACPI, and id_table */
	if (!t->var)
		return -ENODEV;

	t->regmap = devm_regmap_init_i2c(client, &tmpd_regmap_config);
	if (IS_ERR(t->regmap))
		return dev_err_probe(dev, PTR_ERR(t->regmap), "regmap\n");

	/* Identify the device before trusting it */
	ret = regmap_read(t->regmap, TMPD_REG_CONF, &conf);
	if (ret)
		return dev_err_probe(dev, ret, "device not responding at 0x%02x\n",
				     client->addr);

	/* Firmware-agnostic properties (Ch. 31 T.4) */
	device_property_read_u32(dev, "acme,alert-high-millicelsius", &t->alert_high_mC);
	device_property_read_u32(dev, "acme,alert-low-millicelsius",  &t->alert_low_mC);

	ret = regmap_update_bits(t->regmap, TMPD_REG_CONF,
				 CONF_SHUTDOWN | CONF_RESOLUTION | CONF_ALERT,
				 FIELD_PREP(CONF_RESOLUTION, 3) | CONF_ALERT);
	if (ret)
		return ret;

	if (client->irq) {
		ret = devm_request_threaded_irq(dev, client->irq,
						NULL, tmpd_alert_thread,
						IRQF_ONESHOT | IRQF_TRIGGER_LOW,
						dev_name(dev), t);
		if (ret)
			return dev_err_probe(dev, ret, "alert irq\n");
	}

	pm_runtime_set_active(dev);
	pm_runtime_set_autosuspend_delay(dev, 1000);
	pm_runtime_use_autosuspend(dev);
	ret = devm_pm_runtime_enable(dev);
	if (ret)
		return ret;

	hwmon = devm_hwmon_device_register_with_info(dev, "tmpdemo", t,
						     &tmpd_chip_info, NULL);
	if (IS_ERR(hwmon))
		return PTR_ERR(hwmon);

	dev_info(dev, "%s at 0x%02x on %s\n", t->var->name, client->addr,
		 client->adapter->name);
	return 0;
}

static int tmpd_suspend(struct device *dev)
{
	struct tmpd *t = dev_get_drvdata(dev);

	regcache_cache_only(t->regmap, true);        /* ★ Ch. 34 T.7 */
	regcache_mark_dirty(t->regmap);
	return regmap_update_bits(t->regmap, TMPD_REG_CONF, CONF_SHUTDOWN, CONF_SHUTDOWN);
}
static int tmpd_resume(struct device *dev)
{
	struct tmpd *t = dev_get_drvdata(dev);

	regcache_cache_only(t->regmap, false);
	return regcache_sync(t->regmap);             /* restores every register */
}
static DEFINE_RUNTIME_DEV_PM_OPS(tmpd_pm, tmpd_suspend, tmpd_resume, NULL);

static const struct i2c_device_id tmpd_ids[] = {
	{ "tmpdemo",    (kernel_ulong_t)&tmpd_v1 },
	{ "tmpdemo-v2", (kernel_ulong_t)&tmpd_v2 },
	{ }
};
MODULE_DEVICE_TABLE(i2c, tmpd_ids);

static const struct of_device_id tmpd_of_ids[] = {
	{ .compatible = "acme,tmpdemo",    .data = &tmpd_v1 },
	{ .compatible = "acme,tmpdemo-v2", .data = &tmpd_v2 },
	{ }
};
MODULE_DEVICE_TABLE(of, tmpd_of_ids);

static struct i2c_driver tmpd_driver = {
	.driver = {
		.name           = "tmpdemo",
		.of_match_table = tmpd_of_ids,
		.pm             = pm_ptr(&tmpd_pm),
	},
	.probe    = tmpd_probe,
	.id_table = tmpd_ids,
};
module_i2c_driver(tmpd_driver);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("I2C temperature sensor reference driver");
```

### Lab 40.4 — Userspace I²C via `/dev/i2c-N`

```c
/* i2cuser.c — gcc -O2 -o i2cuser i2cuser.c */
#include <fcntl.h>
#include <linux/i2c.h>
#include <linux/i2c-dev.h>
#include <stdio.h>
#include <string.h>
#include <sys/ioctl.h>
#include <unistd.h>

int main(int argc, char **argv)
{
	int bus = atoi(argv[1]), addr = strtol(argv[2], NULL, 0);
	char path[32];
	unsigned long funcs;
	int fd;

	snprintf(path, sizeof(path), "/dev/i2c-%d", bus);
	fd = open(path, O_RDWR);

	/* ★ T.3: always check functionality first */
	ioctl(fd, I2C_FUNCS, &funcs);
	printf("funcs: I2C=%d SMBUS_BYTE_DATA=%d SMBUS_WORD_DATA=%d SMBUS_BLOCK=%d\n",
	       !!(funcs & I2C_FUNC_I2C), !!(funcs & I2C_FUNC_SMBUS_BYTE_DATA),
	       !!(funcs & I2C_FUNC_SMBUS_WORD_DATA), !!(funcs & I2C_FUNC_SMBUS_BLOCK_DATA));

	/* Raw transfer with a REPEATED START (T.3) */
	{
		unsigned char reg = 0x00, data[2];
		struct i2c_msg msgs[2] = {
			{ .addr = addr, .flags = 0,        .len = 1, .buf = &reg },
			{ .addr = addr, .flags = I2C_M_RD, .len = 2, .buf = data },
		};
		struct i2c_rdwr_ioctl_data rdwr = { .msgs = msgs, .nmsgs = 2 };

		if (ioctl(fd, I2C_RDWR, &rdwr) < 0)
			perror("I2C_RDWR");
		else
			printf("reg 0x00 = 0x%02x%02x\n", data[0], data[1]);
	}

	/* SMBus helper form */
	{
		struct i2c_smbus_ioctl_data args;
		union i2c_smbus_data d;

		ioctl(fd, I2C_SLAVE, addr);
		args.read_write = I2C_SMBUS_READ;
		args.command = 0x01;
		args.size = I2C_SMBUS_WORD_DATA;
		args.data = &d;
		if (ioctl(fd, I2C_SMBUS, &args) == 0)
			printf("smbus word 0x01 = 0x%04x\n", d.word);
	}
	close(fd);
	return 0;
}
```

1. **Read `drivers/i2c/algos/i2c-algo-bit.c`** completely. It is the I²C protocol as
   executable C. Identify START, repeated START, STOP, ACK/NAK, arbitration-loss detection,
   and clock-stretching handling. Then draw the waveform for a register read.

2. **Wired-AND arbitration.** Explain, with a timing diagram, how two masters transmitting
   `0x48` and `0x4C` resolve. Which wins, at which bit, and how does the loser know?

3. **Clock stretching failures.** Find three controller drivers that document stretching
   limitations (`git grep -i 'clock stretch' drivers/i2c/busses/`). What breaks and how is it
   worked around?

4. **The probing hazard.** Write 300 words for a hardware-bring-up colleague explaining why
   `i2cdetect` without `-r` can damage a board, with a concrete example. Then read
   `Documentation/i2c/instantiating-devices.rst` and state the correct approach.

5. **SMBus vs I²C.** For each SMBus transaction type, write the exact wire sequence. Then
   find a device whose protocol is *not* SMBus-shaped and explain why it needs raw
   `i2c_transfer()`.

6. **Repeated start.** Construct the race that occurs on a multi-master bus if a driver does
   two separate `i2c_transfer()` calls instead of one two-message transfer. Then find a real
   driver that gets this right and one that does not.

7. **Threaded IRQ necessity.** Explain precisely what happens if you register a *hardirq*
   handler that calls `i2c_smbus_read_byte_data()`. Build it and read the splat

8. **Bus recovery.** Read `i2c_generic_scl_recovery()`. Explain why 9 clock pulses, and what

9. **Mux locking.** Read `Documentation/i2c/i2c-topology.rst`. Explain the difference between

10. **Atomic transfers.** Find a driver that uses I²C in its poweroff path
    (`git grep -l 'i2c' drivers/power/reset/`). How does it avoid sleeping? Which controllers

11. **Design question.** A board has: a PMIC at 0x34 (must be reachable at poweroff), four
