# Chapter 54 — VFS II: path walking, RCU-walk, the dcache, and namespaces

> **Goal:** Understand path resolution — the single hottest operation in the kernel — as a genuine algorithmic and concurrency problem rather than a string-splitting exercise. Understand why the dentry cache exists in the shape it does, why Linux has *two* path walkers and switches between them mid-walk, how a lockless walk can be correct when directories are being renamed underneath it, why `rename()` has the hardest lock ordering in the kernel, why every "resolve this path safely" attempt before `openat2()` was broken, and how namespaces make "the same path" mean different things to different processes. By the end you can read `fs/namei.c`, explain every field of `struct nameidata`, and reason about path-based TOCTOU races precisely.

---

## Theory & First Principles

### T.0 — Start here: resolving one path, 40,000 times a second

```bash
strace -c -e trace=openat,stat,newfstatat ls -R /usr >/dev/null 2>/tmp/s; tail -5 /tmp/s
sudo /usr/share/bcc/tools/dcstat 1      # REFS/sec on a busy machine
```

On a loaded server, path resolution runs **tens to hundreds of thousands of times per
second**. Every `open`, `stat`, `exec`, and `unlink` starts with it. It is plausibly the
hottest single code path in the kernel.

Now look at what it has to do for `open("/usr/lib/libc.so.6")`:

```
  "/"    -> the root dentry
  "usr"  -> look up "usr" in / , check permissions, is it a symlink? a mount point?
  "lib"  -> look up "lib" in /usr ... same questions
  "libc.so.6" -> ... and again
```

**Four lookups, each of which must handle:** permission checks, symlinks (which restart
resolution), mount points (which cross filesystems), `..` (which may cross *out* of a mount),
negative entries ("this name definitely does not exist"), and concurrent `rename` of any
component at any moment.

**The naive implementation takes a lock on each directory.** Now every process on the machine
contends on the dentry for `/`, and `/usr`, and `/usr/lib` — which is Ch. 16 §T.0's shared
cacheline problem, on the hottest path in the system. It does not scale past a few cores.

**So Linux resolves paths without taking any locks at all**, in the common case:

```
  RCU-WALK   -- no locks, no refcounts, no writes to shared memory.
     |          Uses a SEQLOCK (Ch. 14) per dentry: read the name and the
     |          parent pointer, then re-check the sequence number.
     |          If anything changed underneath, the whole walk is invalid.
     |
     +-- on ANY difficulty (a symlink, a permission that needs
         inode access, a filesystem that may sleep, a seqlock mismatch):
     |
     v
  REF-WALK   -- fall back: take real references and locks, restart from
                where RCU-walk got to (or from the beginning).
```

**Two ideas worth extracting, because both generalize far beyond this chapter:**

1. **An optimistic fast path with a pessimistic fallback.** Try the cheap thing; detect that
   it was invalid; redo it the expensive way. This is the same structure as seqlocks, as
   lock-free algorithms' retry loops, and as transactional memory. It works precisely when
   *failure is detectable and retry is cheap* — and the art is in making detection sound.
2. **The hard part is proving the fast path is safe.** RCU-walk touches a dentry that may be
   freed concurrently. It is safe only because RCU guarantees the memory is not *reused*
   during the walk (Ch. 15), and because the seqlock detects any modification. Getting this
   right took years and it is some of the most carefully-argued code in the kernel.

**And a security dimension that is the reason `openat2()` exists.** Path resolution is
inherently a TOCTOU surface:

```c
if (stat("/tmp/user_file", &st) == 0 && st.st_uid == user)
	fd = open("/tmp/user_file", O_WRONLY);   /* ← swapped for a symlink to
	                                             /etc/shadow in between */
```

The `*at()` family (taking a directory fd) exists to pin the starting point; `O_NOFOLLOW`,
`RESOLVE_NO_SYMLINKS`, and `RESOLVE_BENEATH` in `openat2()` exist to constrain what
resolution may do. **A container runtime that resolves a path without these is escapable**
(Ch. 93), which is why this is not merely a performance chapter.

```bash
cat /proc/sys/fs/dentry-state       # nr_dentry, nr_unused, age limit
sudo /usr/share/bcc/tools/dcstat 1
sudo bpftrace -e 'kprobe:link_path_walk { @[str(arg1)] = count(); }'
sudo perf record -e 'fs:*' -a -- sleep 5 && sudo perf report --stdio | head
```

### T.1 Path resolution is the kernel's hottest operation

Every `open`, `stat`, `execve`, `unlink`, `mount`, and `chdir` begins by turning a string into a `(vfsmount, dentry)` pair. On a busy system this happens millions of times per second. A single `execve` of a dynamically linked binary can trigger dozens of path lookups as `ld.so` searches for libraries — most of which *fail*, walking through several directories before finding the right one.

The cost structure is brutal:

| Step | Cost if uncached |
|---|---|
| Read a directory block from disk | 20 µs – 10 ms |
| Search it for a name | O(entries) or O(log n) with an index |
| Instantiate an inode | another disk read |
| **Repeat per component** | × depth |

Resolving `/usr/lib/x86_64-linux-gnu/libc.so.6` uncached is five directory reads plus five inode reads. At 100 µs each that is a millisecond, for one library, in one process.

So path resolution has two requirements that pull in opposite directions:

1. **It must almost never touch the disk.** Hence the dcache (§T.3).
2. **It must scale to hundreds of cores hitting the same hot directories.** Every process walks `/`, `/usr`, `/lib`. A lock on `/`'s dentry is a global lock. Hence RCU-walk (§T.4).

The second requirement is the interesting one, and it is why `fs/namei.c` is one of the most intricate files in the kernel. It is also why Al Viro's name appears in nearly every commit to it.

### T.2 The naive algorithm, and each way it fails

```
resolve(path):
    if path starts with '/': cur = root
    else: cur = cwd
    for component in split(path, '/'):
        if component == '.': continue
        if component == '..': cur = parent(cur); continue
        cur = lookup(cur, component)     # may hit disk
        if cur is a symlink: recurse on its target
        if cur is a mountpoint: cur = root of the mounted fs
    return cur
```

Correct, and wrong in six ways:

| Failure | Why |
|---|---|
| **Disk access per component** | unacceptable; fixed by the dcache (§T.3) |
| **Refcount traffic on hot dentries** | every walk takes and drops a reference on `/`; an atomic on a shared cache line, per component, per walk. Measured to be a real ceiling. Fixed by RCU-walk (§T.4). |
| **`parent()` can race with `rename`** | the parent pointer can change mid-walk; fixed by seqlocks (§T.5) and `rename_lock` |
| **Symlink recursion is unbounded** | loops and deep nesting; fixed by explicit limits (§T.7) |
| **Mount crossing is not a simple pointer** | one dentry can have several mounts on it; fixed by the mount hash (§T.8) |
| **Every check is a TOCTOU window** | "is this path inside my sandbox?" cannot be answered by checking then opening (§T.9) |

Each section below is one of those six.

### T.3 The dcache: a cache whose job is to avoid the filesystem entirely

The dentry cache is a hash table keyed by `(parent dentry, name hash)`:

```c
static struct hlist_bl_head *dentry_hashtable;

static inline struct hlist_bl_head *d_hash(unsigned int hash)
{
	return dentry_hashtable + (hash >> d_hash_shift);
}
```

The key point is that the key is **`(parent, name)`, not the full path**. That is what makes the cache *compositional*: `/usr/lib/foo` and `/usr/lib/bar` share the cached lookup of `/usr` and `/usr/lib`, and a walk of any path through `/usr` benefits from every previous walk.

The hash combines the parent pointer with the name:

```c
	hash = init_name_hash(parent);
	for each char c in name:
		hash = partial_name_hash(c, hash);
	hash = end_name_hash(hash);
```

`hlist_bl` (bit-spinlock hlist) is used rather than a plain hlist: the lock bit lives in the *head pointer's* low bit, so the hash table has no separate lock array. With a table of millions of buckets, a separate spinlock per bucket would cost more memory than the entries. This is a real space/complexity trade and a good example of the kind of micro-design that goes into a structure this hot.

Three properties make the dcache work:

**(a) It caches negative results.** `d_inode == NULL` means "this name definitively does not exist." Since `ld.so` searches multiple directories and most lookups fail, negative dentries prevent a disk read per failure. On a typical system they are 30–60 % of the dcache.

**(b) It is a cache, so it can be dropped.** Nothing in the dcache is authoritative except while referenced. This bounds memory and lets the shrinker (Ch. 53 §1.4) reclaim it.

**(c) The filesystem is consulted only on a miss.** `->lookup()` is called with the parent's `i_rwsem` held (shared), the filesystem finds the name on disk, and calls `d_add()`/`d_splice_alias()` to populate the dentry. After that, the filesystem is not involved — which is why local filesystems need no `d_revalidate` and why network filesystems do.

The hit rate is extraordinarily high in practice — typically 95–99.9 % — which is what makes the whole storage stack feel fast.

### T.4 Two walkers: RCU-walk and REF-walk

Here is the central design of this chapter.

Even with a perfect cache hit rate, the naive walk takes a reference on each dentry as it goes:

```c
	dentry = d_lookup(parent, &name);   /* takes d_lockref.count++ */
	dput(parent);
	parent = dentry;
```

On a 64-core machine where every process walks through `/`, that is 64 cores doing atomic RMW on one cache line. The line ping-pongs, and throughput collapses exactly as Ch. 16 §T.1 predicts. Measurements around 2010 showed path lookup was a hard scalability ceiling for anything doing lots of `open()`.

Nick Piggin's solution (2.6.38, 2011), refined by Al Viro since, is to have **two walkers**:

| | **RCU-walk** | **REF-walk** |
|---|---|---|
| Takes references? | **no** | yes (`dget`/`dput`) |
| Takes locks? | **no** | `i_rwsem` shared on directories |
| Protected by | `rcu_read_lock()` + seqlocks | reference counts |
| Can it sleep? | **no** | yes |
| Can it call `->lookup()`? | **no** (would sleep) | yes |
| Speed | very fast; **no shared writes at all** | slower |
| Failure mode | bail out and restart in REF-walk | none |

The walk **starts in RCU-walk** and stays there as long as everything is cached and nothing is contended. The moment it needs to do something RCU-walk cannot — sleep, take a reference, call into the filesystem — it attempts to **drop out** into REF-walk (§T.6).

This is a *speculative execution* design: assume the fast case, detect violation, fall back. The same shape as optimistic concurrency control in databases, as seqlocks (Ch. 14 §T.9), and as hardware transactional memory. The correctness burden is entirely in the *detection*.

The payoff is that in the common case — every component cached, no contention — a full path walk performs **zero shared writes**. Not zero atomics: zero writes to any cache line another CPU might have. That is what makes it scale linearly.

### T.5 How a lockless walk can be correct

RCU-walk reads dentries without holding references. The dentry could be freed, renamed, or have its inode swapped underneath. Three mechanisms make it safe.

**(a) RCU delays the free.** Dentries are freed via `call_rcu()`, so within `rcu_read_lock()` a dentry pointer remains valid *memory* even after `__dentry_kill()`. It may be garbage, but it will not be unmapped or reused as something else. This is Ch. 15's basic guarantee.

**(b) `d_seq` detects mutation.** Each dentry has a `seqcount_spinlock_t d_seq`, bumped whenever its name, parent, or inode changes:

```c
	seq = read_seqcount_begin(&dentry->d_seq);
	/* read d_name, d_parent, d_inode ... */
	if (read_seqcount_retry(&dentry->d_seq, seq))
		goto retry;             /* it changed under us */
```

So a lookup reads the fields, then checks whether they were stable across the read. This is a seqlock used as a *validity stamp* rather than as a lock.

**(c) `rename_lock` detects tree reshaping.** A global `seqlock_t rename_lock` is write-taken by `d_move()` (rename). A walk that traverses `..` or otherwise depends on tree structure samples it and re-checks. A rename anywhere invalidates every in-flight RCU-walk that cared — coarse, but renames are rare and the check is a single read of an uncontended cache line.

The validation chain at the end of a walk is:

```c
	/* try_to_unlazy(): convert RCU-walk state into REF-walk state */
	if (!lockref_get_not_dead(&dentry->d_lockref))
		goto out;                            /* it died */
	if (read_seqcount_retry(&dentry->d_seq, nd->seq))
		goto out_dput;                       /* it changed */
	if (!legitimize_mnt(nd->path.mnt, nd->m_seq))
		goto out_dput;                       /* the mount went away */
```

If all three pass, the speculative walk is retroactively legitimised: we now hold real references and the state we observed was consistent. If any fails, the entire walk is abandoned and restarted from scratch in REF-walk mode.

**Restarting from scratch** is the key simplification. Rather than trying to repair a partially-invalid walk, the code throws it away. Because the failure rate is low, the amortised cost is negligible, and the code is vastly simpler than any incremental-repair scheme would be. This is a design lesson worth generalising: *when the fast path is overwhelmingly common, make the slow path simple rather than efficient.*

### T.6 Dropping out: when RCU-walk gives up

RCU-walk must abandon the fast path whenever it needs to do something that requires sleeping or a reference. The complete list:

| Trigger | Why |
|---|---|
| dcache miss | `->lookup()` may sleep and do I/O |
| `->d_revalidate` needed (NFS, FUSE) | may do RPC |
| `->permission` that may sleep (some LSMs, POSIX ACLs not cached) | |
| Symlink whose target is not cached (`->get_link` may sleep) | |
| `->d_automount` (autofs) | may trigger a mount |
| Crossing into a filesystem that needs it (`LOOKUP_NO_REVAL` violations) | |
| The final component when the operation needs `i_rwsem` (create, unlink) | |
| A seqcount retry failure | the state we read was torn |
| `mount_lock` sequence changed | the mount tree moved |

`try_to_unlazy()` and `try_to_unlazy_next()` attempt the conversion in place. If they succeed, the walk continues in REF-walk from the current position — no restart. If they fail (the dentry died or changed), the walk restarts from the beginning with `LOOKUP_REVAL` set.

The statistics are observable and instructive (Lab 54.3): on a warm system, the overwhelming majority of walks complete entirely in RCU-walk.

`ENOENT` handling deserves a note: a *negative* dentry found in RCU-walk is a valid result. The walk can conclude "this path does not exist" without ever taking a reference or a lock, which is why failed lookups are cheap once cached — important given how many lookups fail.

### T.7 Symlinks: recursion with a budget

A symlink's target is itself a path, resolved in the context of the symlink's parent. That is recursion, and recursion in the kernel needs a bound.

Two limits, both in `struct nameidata`:

```c
#define MAXSYMLINKS 40          /* total symlinks followed in one resolution */
#define EMBEDDED_LEVELS 2       /* stack slots inlined in nameidata */

	struct saved {
		struct path link;
		struct delayed_call done;
		const char *name;
		unsigned seq;
	} *stack, internal[EMBEDDED_LEVELS];
	unsigned depth;
	int total_link_count;
```

The design points:

**(a) Iteration, not recursion.** `link_path_walk()` does not call itself. It maintains an explicit stack of pending symlink continuations, so the kernel stack depth is O(1) regardless of symlink nesting. Kernel stacks are 16 KiB (Ch. 20); unbounded recursion here would be a trivially exploitable stack overflow.

**(b) Two separate limits.** `depth` bounds *nesting* (a symlink whose target contains a symlink…). `total_link_count` bounds the *total* followed in one resolution, catching the case of many sibling symlinks that individually nest shallowly. Both are needed; a path like `a/b/c/d/...` where every component is a symlink has depth 1 but a high total.

**(c) The first two levels are inline.** `internal[EMBEDDED_LEVELS]` avoids an allocation for the common case. Deeper nesting allocates `stack` from the heap. Classic small-size optimisation, in the hottest path.

**(d) `->get_link()` has an RCU mode.** It is called with `dentry == NULL` when in RCU-walk; filesystems that can return a cached target (`simple_get_link`, or ext4's fast symlinks stored inline in the inode) do so and the walk stays fast. Filesystems that must read a block return `ERR_PTR(-ECHILD)`, forcing the dropout. This is the same "provide a non-sleeping variant when you can" pattern as `gpiod_get_value` vs `_cansleep` (Ch. 42 §T.6).

Symlink loops are detected by the counters, not by cycle detection — the kernel does not track visited nodes. A 41-deep chain and a 2-cycle both fail with `ELOOP`, which is correct and vastly cheaper than maintaining a visited set.

### T.8 Crossing mounts

A dentry that is a mountpoint has one or more mounts on it. Crossing is not "follow a pointer" because the answer depends on *which* mount you arrived through — the mount tree is per-namespace, and the same dentry can be a mountpoint in one namespace and not in another.

```c
static bool __follow_mount_rcu(struct nameidata *nd, struct path *path)
{
	for (;;) {
		struct mount *mounted = __lookup_mnt(path->mnt, path->dentry);

		if (!mounted)
			break;
		path->mnt = &mounted->mnt;
		path->dentry = mounted->mnt.mnt_root;
		nd->state |= ND_JUMPED;
		nd->next_seq = read_seqcount_begin(&path->dentry->d_seq);
	}
	return true;
}
```

The loop matters: mounts can be **stacked** (mount A on `/mnt`, then mount B on `/mnt`), and the visible one is the topmost. `__lookup_mnt()` searches a hash keyed by `(parent mount, mountpoint dentry)`.

`mount_lock` is a seqlock protecting the mount hash. RCU-walk reads it without locking and validates at the end via `legitimize_mnt()`; REF-walk takes a real reference with `mntget()`.

Going *up* through `..` is asymmetric and harder:

- If the current dentry is the root of a mount, `..` must jump to the *mountpoint* in the parent mount, then take the parent of that.
- If the current dentry is the root of the **namespace's** root (or the process's `chroot` root), `..` stays put — this is what makes `chroot` and `pivot_root` contain a process at all.
- The mount could be unmounted concurrently, so `follow_dotdot()` must validate.

`follow_dotdot_rcu()` handles this with a loop that re-reads `mount_lock` each iteration. The `..`-at-a-mount-root case is a recurring source of subtle bugs and of container escapes (§T.9).

### T.9 Path-based security is a TOCTOU minefield

Here is the deepest practical lesson in the chapter.

A privileged program wants to open a file only if it is inside `/var/www`. The obvious approach:

```c
	realpath(user_path, resolved);
	if (strncmp(resolved, "/var/www/", 9) != 0)
		return -EPERM;
	fd = open(resolved, O_RDONLY);      /* <-- RACE */
```

Between the check and the open, an attacker replaces a component with a symlink to `/etc/shadow`. This is the classic **TOCTOU** (time-of-check-to-time-of-use) race, and it is **unfixable in userspace** because path resolution is not atomic with respect to the check.

Partial mitigations, all inadequate:

| Approach | Why it fails |
|---|---|
| `O_NOFOLLOW` | only checks the *final* component |
| `realpath()` then compare | the race above |
| Open each component with `openat` + `O_NOFOLLOW` + `O_PATH` | works, but is O(depth) syscalls and is very easy to get wrong (`..`, mounts, bind mounts) |
| `chroot()` | requires privilege, and `..` escapes are well known |
| Compare `st_dev`/`st_ino` after opening | narrows but does not close the window |

**`openat2()` (5.6+) fixes it in the kernel**, where resolution is already a single operation:

```c
struct open_how how = {
	.flags = O_RDONLY,
	.resolve = RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS |
		   RESOLVE_NO_XDEV | RESOLVE_NO_MAGICLINKS,
};
fd = syscall(__NR_openat2, dirfd, path, &how, sizeof(how));
```

The `RESOLVE_*` flags:

| Flag | Meaning |
|---|---|
| `RESOLVE_BENEATH` | the path must not escape `dirfd`; **`..` and absolute paths are rejected** |
| `RESOLVE_IN_ROOT` | treat `dirfd` as `/` — a `chroot` for this resolution only, no privilege needed |
| `RESOLVE_NO_SYMLINKS` | no symlinks at all, in any component |
| `RESOLVE_NO_MAGICLINKS` | no `/proc/*/fd/*`-style jumps (these are *not* symlinks and bypass the above) |
| `RESOLVE_NO_XDEV` | do not cross any mount point |
| `RESOLVE_CACHED` | **fail with `-EAGAIN` rather than do I/O** — the fast-path-only flag io_uring uses |

The enforcement happens *inside* `link_path_walk()`, at each component, atomically with the resolution. There is no window.

Two subtleties worth knowing:

**Magic links** (`/proc/PID/fd/N`, `/proc/PID/exe`, `/proc/PID/cwd`) are not symlinks — they have no target string. `->get_link()` returns a `struct path` directly, jumping the walk to an arbitrary place in the tree. `RESOLVE_NO_SYMLINKS` does not block them, which is why `RESOLVE_NO_MAGICLINKS` exists separately. This has been a real escape vector.

**`RESOLVE_CACHED`** is a performance flag with an interesting rationale: `io_uring` wants to do `openat2` from a non-blocking context. Rather than "try and maybe block," the flag says "complete only if you can do so entirely from cache." It is the same idea as `GFP_NOWAIT` — an explicit statement of what the caller can tolerate.

`openat2` is also the first syscall built with Ch. 24 §T.3's extensible-struct pattern (`struct open_how` + size), specifically so future resolve flags need no new syscall.

### T.10 Directory locking and `rename`: the kernel's hardest lock ordering

Creating, unlinking, and renaming require exclusive `i_rwsem` on the affected directory. Ordinary operations take one lock. `rename()` takes up to **four**, and the ordering problem is genuinely hard:

```
rename("/a/x", "/b/y")
```

needs exclusive locks on `/a`, `/b`, and (for directory renames, to prevent a directory becoming its own ancestor) a global serialising lock, plus locks on the source and target inodes.

The rules, from `Documentation/filesystems/directory-locking.rst`:

1. **`s_vfs_rename_mutex`** — a per-superblock mutex taken for *any* cross-directory rename. This serialises all such renames on a filesystem, which is coarse but makes the rest tractable.
2. **Ancestor-first ordering.** If one directory is an ancestor of the other, lock the ancestor first. This requires *checking* ancestry (`is_subdir()`), which itself must be race-free — hence `rename_lock`.
3. **Address ordering otherwise.** If neither is an ancestor of the other, lock in address order.
4. **The loop check.** Renaming a directory into its own subtree would create a cycle and orphan a subtree. `lock_rename()` plus the ancestry check under `s_vfs_rename_mutex` prevents it.

```c
struct dentry *lock_rename(struct dentry *p1, struct dentry *p2)
{
	struct dentry *p;

	if (p1 == p2) {
		inode_lock_nested(p1->d_inode, I_MUTEX_PARENT);
		return NULL;
	}
	mutex_lock(&p1->d_sb->s_vfs_rename_mutex);

	p = d_ancestor(p2, p1);            /* is p2 an ancestor of p1? */
	if (p) {
		inode_lock_nested(p2->d_inode, I_MUTEX_PARENT);
		inode_lock_nested(p1->d_inode, I_MUTEX_CHILD);
		return p;
	}
	p = d_ancestor(p1, p2);
	if (p) {
		inode_lock_nested(p1->d_inode, I_MUTEX_PARENT);
		inode_lock_nested(p2->d_inode, I_MUTEX_CHILD);
		return p;
	}
	lock_two_inodes(p1->d_inode, p2->d_inode,
			I_MUTEX_PARENT, I_MUTEX_PARENT2);
	return NULL;
}
```

`I_MUTEX_PARENT`/`I_MUTEX_CHILD`/`I_MUTEX_PARENT2` are **lockdep subclasses** (Ch. 14): they tell lockdep "these are the same lock class but a known safe nesting," so it does not report a false ABBA. Getting these annotations wrong produces either false positives that train people to ignore lockdep, or missed real deadlocks.

Then `d_move()` performs the dcache side atomically: it moves the dentry to its new parent, updates hashes, and bumps `rename_lock` so every in-flight RCU-walk notices.

The reason this is worth studying even if you never write a filesystem: **it is a worked example of establishing a total order over locks whose identity is discovered at runtime**, which is the general form of the hardest locking problems.

`RENAME_EXCHANGE` (atomic swap of two paths) and `RENAME_NOREPLACE` (fail if the target exists) were added to `renameat2()` because the two-step workarounds were racy. `RENAME_EXCHANGE` in particular is what makes atomic directory swaps possible and is used by container runtimes and by `overlayfs`.

### T.11 Namespaces: "the same path" is not a well-defined phrase

Every path resolution starts from either the process's root or its cwd, both stored in `struct fs_struct`:

```c
struct fs_struct {
	int users;
	spinlock_t lock;
	seqcount_spinlock_t seq;
	int umask;
	int in_exec;
	struct path root, pwd;
};
```

and the mount tree it walks through is `current->nsproxy->mnt_ns`. Consequences:

- **`/etc/passwd` denotes different files in different mount namespaces.** There is no global namespace of paths.
- `chroot()` changes `fs->root`; `pivot_root()` changes it *and* reorganises the mount tree so the old root can be unmounted. Containers use the latter, because `chroot` alone leaves the host's mounts reachable.
- The walk's `..` handling checks against `nd->root`, which is why a `chroot`ed process cannot walk above its root — *provided* it has no fd open to a directory outside it, which is the classic `chroot` escape.

The `nd->root` handling has a subtlety: for an absolute path, the walk starts at `fs->root`; for a relative path it starts at `fs->pwd` or at `dirfd`. In RCU-walk, `nd->root_seq` records the seqcount of the root dentry so a concurrent `chroot`/`pivot_root` is detected.

`LOOKUP_IS_SCOPED` (set by `RESOLVE_BENEATH`/`RESOLVE_IN_ROOT`) makes the scope check happen per-component rather than only at `..`, which is what makes §T.9's guarantee hold against magic links and mount crossings.

### 1.2 `struct nameidata` — the walk's state

```c
struct nameidata {
	struct path	path;           /* where we are now */
	struct qstr	last;           /* the component being resolved */
	struct path	root;           /* the walk's root (chroot/scope) */
	struct inode	*inode;         /* path.dentry->d_inode, cached */
	unsigned int	flags, state;   /* LOOKUP_*, ND_* */
	unsigned	seq, next_seq, m_seq, r_seq;   /* the seqcounts of T.5 */
	int		last_type;      /* LAST_NORM/DOT/DOTDOT/ROOT/BIND */
	unsigned	depth;          /* symlink nesting */
	int		total_link_count;
	struct saved {
		struct path link;
		struct delayed_call done;
		const char *name;
		unsigned seq;
	} *stack, internal[EMBEDDED_LEVELS];
	struct filename	*name;
	struct nameidata *saved;
	unsigned	root_seq;
	int		dfd;
	vfsuid_t	dir_vfsuid;     /* for sticky-bit checks */
	umode_t		dir_mode;
};
```

The four seqcounts are the heart of §T.5:

| Field | Guards |
|---|---|
| `seq` | the current dentry's `d_seq` |
| `next_seq` | the next dentry's, while we are still validating the current one |
| `m_seq` | `mount_lock` — the mount tree |
| `r_seq` | `rename_lock` — tree reshaping |

`LOOKUP_*` flags worth knowing:

```c
LOOKUP_FOLLOW        /* follow a trailing symlink */
LOOKUP_DIRECTORY     /* the result must be a directory */
LOOKUP_PARENT        /* stop at the parent (for create/unlink/rename) */
LOOKUP_RCU           /* we are in RCU-walk */
LOOKUP_REVAL         /* force revalidation; set after a dropout restart */
LOOKUP_OPEN, LOOKUP_CREATE, LOOKUP_EXCL, LOOKUP_RENAME_TARGET
LOOKUP_NO_SYMLINKS, LOOKUP_NO_MAGICLINKS, LOOKUP_NO_XDEV
LOOKUP_BENEATH, LOOKUP_IN_ROOT, LOOKUP_IS_SCOPED
LOOKUP_CACHED        /* RESOLVE_CACHED: fail rather than block */
LOOKUP_EMPTY         /* AT_EMPTY_PATH: "" means dirfd itself */
```

### 1.3 The walk, top to bottom

```
filename_lookup(dfd, name, flags, path, root)
 └─ set_nameidata(); 
    retry with increasing strictness:
      1. path_lookupat(nd, flags | LOOKUP_RCU)     /* fast */
      2. path_lookupat(nd, flags)                  /* ref-walk */
      3. path_lookupat(nd, flags | LOOKUP_REVAL)   /* + revalidate */
```

```
path_lookupat(nd, flags)
 ├─ path_init(nd, flags)
 │    ├─ absolute path?  nd->path = nd->root (fs->root, or dirfd for IN_ROOT)
 │    ├─ relative?       nd->path = fs->pwd  or  dirfd's path
 │    └─ if LOOKUP_RCU: rcu_read_lock(); sample m_seq, r_seq, d_seq
 │
 ├─ link_path_walk(name, nd)                    /* all but the last component */
 │    loop over components:
 │      ├─ hash the component name
 │      ├─ may_lookup(nd)                       /* MAY_EXEC on the directory */
 │      ├─ walk_component(nd, WALK_MORE)
 │      │    ├─ handle_dots() for "." and ".."
 │      │    └─ lookup_fast(nd)
 │      │         ├─ RCU: __d_lookup_rcu() + seqcount validate
 │      │         └─ REF: __d_lookup() + d_revalidate()
 │      │         └─ MISS -> lookup_slow() -> dir->i_op->lookup()
 │      ├─ step_into(): cross mounts, follow symlinks
 │      └─ if symlink: push onto nd->stack, continue with the target
 │
 └─ lookup_last(nd)                             /* the final component */
      └─ (for open) open_last_lookups() -> do_open()
```

`lookup_fast()` is the hot path and is worth reading in full:

```c
static struct dentry *lookup_fast(struct nameidata *nd)
{
	struct dentry *dentry, *parent = nd->path.dentry;

	if (nd->flags & LOOKUP_RCU) {
		dentry = __d_lookup_rcu(parent, &nd->last, &nd->next_seq);
		if (unlikely(!dentry)) {
			if (!try_to_unlazy(nd))
				return ERR_PTR(-ECHILD);
			return NULL;            /* caller does lookup_slow */
		}
		/* Validate the PARENT we came from is still what we thought */
		if (read_seqcount_retry(&parent->d_seq, nd->seq))
			return ERR_PTR(-ECHILD);

		if (unlikely(dentry->d_flags & DCACHE_OP_REVALIDATE)) {
			int status = d_revalidate(dentry, nd->flags);
			if (unlikely(status <= 0)) {
				if (!try_to_unlazy_next(nd, dentry))
					return ERR_PTR(-ECHILD);
				...
			}
		}
	} else {
		dentry = __d_lookup(parent, &nd->last);
		...
	}
	return dentry;
}
```

Note `read_seqcount_retry(&parent->d_seq, nd->seq)` **after** looking up the child: we must confirm the parent was stable across the lookup, because a concurrent `d_move()` could have reparented it.

### 1.4 What `-ECHILD` means

`-ECHILD` is the internal "RCU-walk cannot continue" signal. It never reaches userspace. Seeing it in a filesystem method (`->d_revalidate`, `->permission`, `->get_link`) means "I am being called in RCU mode and I cannot do this without sleeping." Returning it correctly is a requirement for any filesystem that wants to participate in RCU-walk:

```c
static const char *myfs_get_link(struct dentry *dentry, struct inode *inode,
				 struct delayed_call *done)
{
	if (!dentry)
		return ERR_PTR(-ECHILD);    /* RCU mode; we need to sleep */
	/* ... read the target, possibly doing I/O ... */
}
```

Filesystems that always return `-ECHILD` work correctly but force a dropout on every symlink, losing the fast path. `simple_get_link` and ext4's inline symlinks avoid this.

```c
// SPDX-License-Identifier: GPL-2.0
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <sys/stat.h>
#include <time.h>
#include <unistd.h>

static double now(void)
{
	struct timespec ts;
	clock_gettime(CLOCK_MONOTONIC, &ts);
	return ts.tv_sec + ts.tv_nsec / 1e9;
}

int main(int argc, char **argv)
{
	const char *p = argc > 1 ? argv[1] : "/usr/bin/ls";
	struct stat st;
	double t0;
	int i, n = 200000;

	stat(p, &st);                       /* warm */
	t0 = now();
	for (i = 0; i < n; i++)
		stat(p, &st);
	printf("warm stat(%s): %.2f us\n", p, (now() - t0) / n * 1e6);

	/* A deep path costs more: one lookup per component */
	t0 = now();
	for (i = 0; i < n; i++)
		stat("/usr/lib/x86_64-linux-gnu/libc.so.6", &st);
	printf("warm deep stat : %.2f us\n", (now() - t0) / n * 1e6);

	/* A failed lookup (negative dentry) */
	t0 = now();
	for (i = 0; i < n; i++)
		stat("/usr/lib/x86_64-linux-gnu/libnope.so", &st);
	printf("warm ENOENT    : %.2f us\n", (now() - t0) / n * 1e6);
	return 0;
}
```

The ENOENT number is the value of negative dentries: it should be comparable to a successful lookup, not to a disk read.

### Lab 54.2 — Prove RCU-walk scales and REF-walk does not

```c
// SPDX-License-Identifier: GPL-2.0
/* pathscale.c: N threads stat()ing the same deep path. */
#define _GNU_SOURCE
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <time.h>
#include <unistd.h>

static const char *path = "/usr/lib/x86_64-linux-gnu/libc.so.6";
static volatile int stop;
static long counts[128];

static void *worker(void *arg)
{
	long id = (long)arg;
	struct stat st;
	cpu_set_t set;

	CPU_ZERO(&set);
	CPU_SET(id % sysconf(_SC_NPROCESSORS_ONLN), &set);
	pthread_setaffinity_np(pthread_self(), sizeof(set), &set);

	while (!stop) {
		stat(path, &st);
		counts[id]++;
	}
	return NULL;
}

int main(int argc, char **argv)
{
	int n = argc > 1 ? atoi(argv[1]) : 4;
	pthread_t t[128];
	long i, total = 0;

	for (i = 0; i < n; i++)
		pthread_create(&t[i], NULL, worker, (void *)i);
	sleep(3);
	stop = 1;
	for (i = 0; i < n; i++)
		pthread_join(t[i], NULL);
	for (i = 0; i < n; i++)
		total += counts[i];
	printf("%3d threads: %10.0f lookups/sec  (%.0f per thread)\n",
	       n, total / 3.0, total / 3.0 / n);
	return 0;
}
```

```sh

```

Per-thread throughput should stay roughly flat — that is RCU-walk's zero-shared-writes property. Now force REF-walk and repeat:

```sh

# Or observe the dropout rate directly during the scaling test:
```

Then show the contrast with an operation that *must* take references and locks:

```c
// SPDX-License-Identifier: GPL-2.0
/* safe.c: openat2 with RESOLVE_BENEATH. No window exists. */
#define _GNU_SOURCE
#include <fcntl.h>
#include <linux/openat2.h>
#include <stdio.h>
#include <string.h>
#include <sys/syscall.h>
#include <unistd.h>

static int openat2_(int dfd, const char *path, struct open_how *how)
{
	return syscall(__NR_openat2, dfd, path, how, sizeof(*how));
}

int main(int argc, char **argv)
{
	struct open_how how = {
		.flags = O_RDONLY | O_CLOEXEC,
		.resolve = RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS |
			   RESOLVE_NO_XDEV,
	};
	int root = open("/tmp/sandbox", O_PATH | O_DIRECTORY | O_CLOEXEC);
	int fd;
	char buf[128];
	ssize_t n;

	if (root < 0) { perror("open sandbox"); return 1; }

	fd = openat2_(root, argv[1], &how);
	if (fd < 0) { perror("openat2 (correctly refused)"); return 1; }

	n = read(fd, buf, sizeof(buf) - 1);
	if (n > 0) { buf[n] = 0; printf("READ: %.60s\n", buf); }
	return 0;
}
```

```sh

./safe target                             # EXDEV / ELOOP: refused, no race

ln -sfn ../../etc/passwd /tmp/sandbox/target
./safe target                             # refused: .. is blocked by BENEATH
```

```sh
cp /bin/busybox /tmp/jail/bin/ 2>/dev/null || cp /bin/sh /tmp/jail/bin/sh
sudo chroot /tmp/jail /bin/sh -c 'ls /; echo "---"; ls /.. 2>&1'
# `..` at the root stays put -- the walk checks nd->root (T.11)

# But a pre-opened directory fd escapes:
cat > escape.c <<'EOF'
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
int main(void) {
	int fd = open("/", O_RDONLY | O_DIRECTORY);   /* opened BEFORE chroot */
	chroot("/tmp/jail");
	fchdir(fd);                                    /* cwd is now outside */
	for (int i = 0; i < 64; i++) chdir("..");
	chroot(".");
	execl("/bin/sh", "sh", NULL);
}
EOF
# This is the classic chroot escape; it is why containers use pivot_root
# plus mount namespaces plus dropping CAP_SYS_CHROOT.
```

And the scoped-resolution alternative that needs no privilege:

```sh
# RESOLVE_IN_ROOT gives chroot-like scoping per-resolution, unprivileged
./safe_in_root /etc/passwd     # resolves to /tmp/sandbox/etc/passwd
```

### Lab 54.8 — Instrument dcache health

```sh
cat /proc/sys/fs/dentry-state
# nr_dentry  nr_unused  age_limit  want_pages  nr_negative  nr_dentry_negative

# The negative-dentry fraction
awk '{printf "total=%d unused=%d negative=%d (%.1f%%)\n",
      $1, $2, $6, 100*$6/$1}' /proc/sys/fs/dentry-state

# Hash table stats
sudo bpftrace -e '
kprobe:__d_lookup_rcu { @calls = count(); }
kretprobe:__d_lookup_rcu {
	if (retval == 0) { @miss = count(); } else { @hit = count(); }
}
interval:s:5 {
	printf("hit=%d miss=%d ratio=%d%%\n", @hit, @miss,
	       @hit * 100 / (@hit + @miss + 1));
	clear(@hit); clear(@miss);
}'
```

Find the hot directories:

```sh
sudo bpftrace -e '
kprobe:lookup_slow {
	$nd = (struct nameidata *)arg0;
	@slow_dirs[str($nd->last.name)] = count();
}
interval:s:10 { print(@slow_dirs, 20); clear(@slow_dirs); }'
```

Measure the cost of a pathological directory:

```sh
mkdir -p /tmp/bigdir && cd /tmp/bigdir
for i in $(seq 1 200000); do touch f$i; done 2>/dev/null

echo 3 | sudo tee /proc/sys/vm/drop_caches
time stat /tmp/bigdir/f199999      # cold: depends on the fs's dir index
time stat /tmp/bigdir/f199999      # warm: dcache hit, O(1)

# ext4 with dir_index (htree) vs without:
sudo tune2fs -l $(findmnt -no SOURCE /tmp) | grep -i features
```

This is where the filesystem's directory structure (Ch. 57's htree, Ch. 58's B+trees) meets the VFS: the dcache makes repeat lookups O(1), but the *first* lookup costs whatever the on-disk structure costs.
